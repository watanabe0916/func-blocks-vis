# 追加・変更ブロックおよび機能メモ

本環境に実装されているカスタムブロックおよびトランスパイラ/可視化機能の要約です。新しいブロックや機能の追加・変更を行った際は、このメモを更新してください。

---

## -1. 実行パイプラインの5段階分離（関数型ASTの独立・純粋評価器・トレース駆動グラフ描画）

`CLAUDE.md` §4 の規定に基づき、従来「グラフ構築」と「評価」が `transpiler.ts` 1ファイルに融合していたアーキテクチャを、以下の5段階パイプラインへ全面移行しました。対象は既存4カテゴリ（変数／数学・計算／論理・比較／テキスト出力）ブロックのみで、新規ブロックの追加は行っていません。

### 新設・変更ファイル
- `src/compiler/functionalAst.ts`（新設）：独立した関数型ASTの型定義（`Lit`/`Var`/`Let`/`PrimApp`/`Do`）。React Flow・Zustandに一切依存しない。
- `src/compiler/transpiler.ts`：役割を「①手続型AST→②関数型ASTへの変換」のみに縮小（`transpileToFunctionalAst`。旧`transpileToSSA`は廃止）。評価ロジック・グラフ構築ロジックは一切持たない。
- `src/compiler/evaluator.ts`（新設）：③純粋評価器。`evaluate(program): { trace, consoleOutput }` というUI非依存の純粋関数。Thunk/force/メモ化/BUILTINSは`transpiler.ts`から移設し、UIノードへの直接書き込みを完全に廃止（forceイベントは`trace`配列への push のみ）。
- `src/compiler/renderGraph.ts`（新設）：⑤トレース駆動グラフ描画。`renderGraph(program, trace): { nodes, edges }` という、評価を一切行わない純粋関数。
- `src/components/BlocklyPane.tsx`：`handleRun`が新しい4段階呼び出し（`transpileToFunctionalAst`→`evaluate`→`renderGraph`→`updateGraph`）に変更。
- `src/components/FlowPane.tsx`：ノードのHandle位置を左右（Left/Right）から上下（Top/Bottom）へ変更（後述のレイアウト方向転換に対応）。

### 視覚設計原則の採用（Weck & Tichy論文 / `DateFlow.md`）
- **レイアウトを上→下に統一**（従来は左→右）。`renderGraph.ts`内のレイアウト計算は、深さ＝Y・兄弟の広がり＝Xという軸の入れ替えにより実現。
- **全エッジに静的型ラベル（Number/String/Boolean）を付与**。演算子の型はforceを伴わない静的推論（PrimAppの返り値型はopから一意に決まる、Litはtypeofから、Varは束縛元を再帰的に辿る）で決定するため、未評価（ゴースト）ノードへ向かうエッジにも型ラベルが表示される。

### 既知の変更点・制限
- 全Print文は、元のソースコード上の記述位置に関わらず、実行パイプライン上は単一の終端`Do`ノードへ集約される（評価順序はプログラム順のまま維持されるが、グラフ上の水平位置は「全Let列→全Print列」の順で配置される）。
- `CLAUDE.md` §4.6（`haskellPrinter.ts` + GHC差分テストによるCI検証オラクル）は、開発環境に`ghc`/`runghc`が存在せず動作検証ができないため、今回は見送りました。次回以降の課題です。
- テストフレームワークとして `vitest` を新規導入し（`npm run test`）、評価器・グラフ描画それぞれについて単体テストを追加しました（`src/compiler/evaluator.test.ts` / `src/compiler/renderGraph.test.ts`）。ビルド・リンター・自動テストは全て合格を確認済みですが、この開発環境にはブラウザ自動操作ツールが無く、実際のBlockly UIでのクリック操作・画面表示の目視確認は未実施です。

### 「変数」ツールボックスカテゴリの修正（複数変数対応）
- Blockly標準の動的カテゴリ（`custom: 'VARIABLE'`）は、`variable_blocks`スタイルとして登録されている標準ブロック`math_change`（「xを1増やす」相当）を自動的にフライアウトへ混入させてしまうため、一時的に`variables_set`/`variables_get`のみの静的カテゴリへ置き換えていた。しかしこの静的カテゴリには「新しい変数を作成」の導線が無く、ドラッグされる全ブロックがBlocklyの単一デフォルト変数を共有してしまい、いずれかのブロックで変数名を変更すると他の全ブロックの変数名も連動して変わる（＝複数の独立した変数を作成できない）という不具合が発生した。
- `workspace.registerToolboxCategoryCallback('CUSTOM_VARIABLE', ...)` を用い、`Blockly.Variables.flyoutCategory(ws, false)`（標準の動的フライアウト生成結果：変数作成ボタン・変数ごとのget/setブロックを含む）から`type === 'math_change'`のブロックだけを除外する方式に変更した。これにより「複数変数の作成・個別の名前変更」という標準機能を維持したまま、不要な`math_change`ブロックの混入のみを防いでいる。

## 0. 評価モデルの全面刷新（call-by-need / 真の遅延評価）

`CLAUDE.md` の規定に基づき、評価モデルを Launchbury の自然意味論に基づく **call-by-need**（真の遅延評価）へ全面刷新しました。対象は既存の4カテゴリ（変数／数学・計算／論理・比較／テキスト出力）ブロックのみで、新規ブロックの追加は行っていません。

### 演算子の第一級関数適用への統一
- 算術演算（`Add`/`Sub`/`Mul`/`Div`/`Pow`/`Mod`）と比較・論理演算を、AST上で単一の `ApplyNode` に統合しました（従来は `ArithmeticNode` と `ApplyNode` に分裂していました）。すべての演算子は「特殊構文」ではなく「第一級関数適用」として一様に扱われます。

### Thunkベースの2パス評価（トランスパイラの中核刷新）
- `src/compiler/transpiler.ts` を、**Pass 1（構造構築）** と **Pass 2（需要駆動評価）** の2段階に分離しました。
  - Pass 1: ASTを走査し、短絡評価で読まれない可能性がある部分も含めて **すべての部分式を無条件にノード/エッジ化** します。この時点では一切の値計算は行いません（全ノードは `unevaluated`）。
  - Pass 2: 仮想コンソールへの出力（`Print`文）を **需要の根（root of the demand spine）** とし、そこから `force()` を辿って実際に必要な部分だけを評価します。需要が届かなかったノード（短絡された右辺、印字も他の計算にも使われない変数など）は最後まで `unevaluated` のまま残ります。
- **短絡評価は特殊分岐として実装されていません。** `And`/`Or` は他の演算子と同じ `BUILTINS` テーブル上の通常の（非正格な）組込関数として定義されており（例: `Or: (a) => force(a[0]) ? true : force(a[1])`）、右辺が force されないという挙動は遅延評価から自然に創発します。
- Thunkは「未評価（計算を再現するクロージャを保持）」「評価済み（値をメモ化保持）」の2状態FSMとして `types.ts` に定義され（`Thunk`/`Env`型）、一度forceされた値は再計算されずキャッシュされます（メモ化はコード上「observationally pureなbenign effect」として明記）。

### 未評価（ゴースト）状態の可視化と仕様変更
- ノードは `data.evalState`（`'unevaluated' | 'evaluated'`）を持ちます。未評価ノードは減光表示（ゴースト）され、構造は保ったまま結果を表示しません。
- **【仕様変更】** 従来、And/Orの短絡評価時には右辺のノード自体が生成されず非表示でしたが、刷新後は右辺の部分式（ノード・エッジ）は必ずグラフ上に生成され、force されなかった場合はゴースト（減光・展開状態）としてそのまま可視化されます。「計算がスキップされた」ことが、ノードの消失ではなく明示的な未評価状態として観測できるようになりました。
- 評価済みの演算子ノードには、forceされなかった入力（該当があれば）を示す汎用バッジ「need未到達の入力あり」を表示します（従来のAnd/Or専用の「短絡評価」バッジを置き換え）。
- エッジは、供給元ノードが評価済みの場合のみアニメーション表示され、ゴーストへ向かうエッジは破線・減光表示になります。

### 未束縛変数と0除算の健全な扱い
- 未割り当ての変数を参照した場合、クラッシュせず「未束縛」ゴーストノード（⊥）としてグラフ化されます。実際にforceされた場合のみ制御されたエラーとして扱われ、該当する `Print` 文はコンソールにエラー行を出力しつつ、後続の `Print` 文の処理は継続されます（1箇所の需要失敗がシステム全体をクラッシュさせません）。
- 0除算・0剰余は、黙って0を返す特殊処理を撤去し、IEEE754のネイティブ挙動（`Infinity`/`-Infinity`/`NaN`）に委ねるようにしました。

### Elision（折りたたみ簡約表示）の再定義
- 折りたたみ（Elision）は「force済み（評価済み）かつメモ化されたThunkで、入力がリテラルのみ、または埋め込みリテラルを持つノード」として再定義されました。未評価のノードは折りたたまれず、常に展開されたゴースト状態で表示されます。

### textブロックの復元
- 文字列リテラルブロック（`text`）が「テキスト出力」カテゴリのツールボックスに存在せず作成不可能だったため復元しました。`extractor.ts` 側は既に対応済みでしたが未接続だったため、`logic_compare_ext` のString型比較機能が実質的に到達不能でした。

### 既知の制限
- `variables_get` ブロックは型無しの動的変数であるため、比較ブロックの型バリデーション（`logic_compare_ext` の `onchange` フック）は変数同士の比較をすり抜けます（リテラル絡みの比較のみ検出可能）。変数の静的型推論は未実装で、今後の課題です。
- 折りたたみ状態（`foldedNodeIds`）のセッションをまたいだ永続化、および需要・値伝播のタイムライン的なアニメーション演出は今回のスコープ外です。

## 1. 数学・計算 / 変数関連の拡張
### 複合代入ブロック (`math_change_ext`)
- **ブロック機能**: 指定した変数に算術演算（`+=`, `-=`, `*=`, `/=`, `^=`, `%=`）を施し、その結果で変数自体を更新（再代入）します。
- **データフロー変換**: 変数の再代入が発生した際、静的単一代入（SSA）の考え方に則って自動的に「新しいバージョン（例: `x_2`）」の変数ノードを作成し、計算ノードからエッジを接続します。

### 剰余演算（%）の追加
- **ブロック機能**: 標準の算術演算ブロック (`math_arithmetic`) の選択肢に、剰余演算（`%`, `MODULO`）を追加しました。

## 2. 論理・比較演算子ブロック
Boolean を扱う演算子群です。型制約が厳密に定義されています。

### 真偽値ブロック (`logic_boolean_ext`)
- **ブロック機能**: `true` または `false` の真偽値リテラルを出力するブロックです。
- **コネクタ型**: 出力 `Boolean`

### 比較ブロック (`logic_compare_ext`)
- **ブロック機能**: 2つの入力値（数値または文字列）の大小関係や一致判定を行います（`=`, `≠`, `<`, `≤`, `>`, `≥`）。
- **コネクタ型**: 入力 A, B（`Number` または `String`）、出力 `Boolean`
- **バリデーション機能**: 左右に入力されたブロックの型が一致していない場合（例: 数値と文字列を比較しようとした場合）、警告が表示され自動的に接続が解除（切断）されます。

### 論理演算ブロック (`logic_operation_ext`)
- **ブロック機能**: 2つの真偽値入力の論理積（`AND`）または論理和（`OR`）を計算します。
- **コネクタ型**: 入力 A, B（`Boolean`）、出力 `Boolean`

### 否定ブロック (`logic_negate_ext`)
- **ブロック機能**: 入力された真偽値を反転（`NOT`）させます。
- **コネクタ型**: 入力（`Boolean`）、出力 `Boolean`

## 3. トランスパイラと React Flow 可視化機能
手続型のブロックのつながりを、純粋関数型のデータフローに可視化・変換する際の独自機能です。

### 演算子の純粋関数適用化
- 比較・論理演算は内部で `Apply(Operator, [Args...])` の純粋な関数適用に変換して処理します。これにより、将来的な高階関数（部分適用など）への引き渡しが可能になっています。

### エッジの左右（左辺・右辺）の視覚的区別（マルチポート化）
- 算術演算や論理・比較演算（二項演算）は、左辺と右辺の順序が意味を持つため、演算ノード（`opNode`）の入力ターゲットピンを2つに分割（上側の `left` ピンと下側の `right` ピン）しました。
- 各ノードの左端に小さく `L`（左辺）と `R`（右辺）の視覚的ラベルを表示し、それぞれの入力ピンに正確にエッジが接続（`targetHandle: 'left' / 'right'`）されるようにすることで、グラフ上のどこから計算が入力されているかを一目で判別できるように改善しました。

### 短絡評価（遅延評価）
- `AND` / `OR` のトランスパイル時、左辺の結果から全体の判定が確定する場合（例: `false AND ...`）、右辺の評価を完全にスキップ（Thunk化）します。これにより、右辺に未定義の変数が存在していてもエラー（クラッシュ）が発生しません。

### Elision（折りたたみ簡約表示）
- `3 < 5` や `true AND false` など、入力がすべてリテラル値の自明な演算については、初期描画時に1つの結果値ノード（例: `3 < 5 → true`）に折りたたんで表示されます。
- ノード上の「**展開 ▽**」ボタンを押すと、隠れていた入力リテラルノード群とエッジが視覚的に展開され、詳細な評価過程を確認できます。

### 部分適用・リテラルの埋め込み
- 変数と比較する演算（例: `x < 5`）の場合、リテラル値 `5` は演算ノードのラベルに埋め込まれ、`< 5` という単一ノードとして表示されます（変数 `x_1` からこのノードへ1本のエッジだけが繋がります）。
- 演算ノードの「**展開 ▽**」ボタンを押すと、埋め込まれていたリテラル `5` を外側のノードとして展開し、エッジが接続された状態を表示できます。

### 階層的レイアウト（Tree Layout）の自動計算
- `(x < 5) AND (x = 5)` のように演算子がネストして呼び出される場合、ノード同士が重なって視覚的に見えづらくなるのを防ぐため、構文木の深さ（ネストレベル）とスパン情報に基づいて各ノードの X、Y 座標を自動的に階層配置するレイアウトアルゴリズムを導入しました。データフローは常に左（葉ノード・入力値）から右（親の式・出力先）へと規則正しく流れるように配置されます。

### ノードの動的サイズ調整と縦幅削減
- `ValNode`（値/変数用）および `OpNode`（演算用）の上下パディングを `2px` (左右 `8px`)、最小高さを `20px` に抑え、境界線を `1.5px` に細くすることで、縦幅を大幅に短縮し極めてスリムな外観に調整しました。
- 従来はデフォルトの React Flow ノード（固定幅 150px）で表示されていた `Print` ノードを、専用のカスタムコンポーネント `PrintNode` として新しく定義・登録しました。これにより、他のノードと同様に縦幅を極限までスリム化し、`width: 'max-content'` と `whiteSpace: 'nowrap'` を適用して、出力された値の長さに合わせて横幅が動的にぴったりとフィットする極小レイアウトを実現しました。
- 全ノードのフォントサイズを `11px` （内部バッジは `8px`）に調整し、`gap: '4px'` でレイアウトを最適化しました。
- 各ノードに `width: 'max-content'` および `whiteSpace: 'nowrap'` を適用したことで、「VALUE」や「VAR」、「PRINT」などのラベル文字が隠れず見える最小幅を維持しつつ、値の桁数や長さが増えた時には自動的に横幅が追従して伸縮するレスポンシブなUIを実現しました。

### ノード選択時の動的ハイライトとエッジ可視化
- グラフ上の任意のノードをクリックした際、そのノードの境界線を鮮やかなオレンジ（`#ff5722`）で強調し、周囲にソフトな光彩（`boxShadow`）を施すアクティブエフェクトを実装しました。
- React Flow標準の `onNodesChange` / `onEdgesChange` をZustandストア側のアクションとして統合しました。これにより、他のノードから別のノードへ直接クリック移動した際やドラッグ時の選択状態が状態管理（Zustand）に即座かつ100%正しく書き込まれ、ノード境界の強調とエッジのハイライト（太いオレンジ実線＋アニメーション実行）が一切の遅延や競合なく完全に連動して変化するロバストな仕組みを実現しました。
- 選択されたノードと無関係なエッジは半透明の薄いグレー（`opacity: 0.3`）に減衰（フェードアウト）し、複雑なデータフローグラフであっても、選択した要素の依存関係が瞬時に識別可能です。背景（空スペース）をクリックすると、選択がクリアされ通常状態に戻ります。
